# Week 1 Assignment — Model a Small Real-World Problem

## Objective

Practice identifying meaningful objects before writing detailed Python classes.

## Task

Choose **one** domain:

1. food delivery;
2. library borrowing;
3. university course registration;
4. vehicle rental.

Write a short requirement description of approximately **5–8 sentences**, then model the domain using object-oriented thinking.

## Deliverables

Your submission must contain:

### 1. Requirement

Describe what the system needs to do in plain language.

### 2. Candidate objects

Identify at least **five** candidate objects/concepts.

### 3. Identity, State, and Behavior

For each candidate object, provide:

```text
Object:
Identity:
State:
Behavior:
```

### 4. Relationships

Describe at least **three relationships** between the objects using plain language.

Examples:

```text
Customer places Order
Order contains OrderItem
OrderItem refers to Product
```

Do not worry about formal UML notation yet.

### 5. Modelling decisions

Answer:

- Which noun from your requirement did you decide **not** to make a class?
- Why?
- Which object was the hardest to model?
- Why?

### 6. Reflection

Write **150–250 words** answering:

> What is different about thinking in objects compared with immediately writing variables and functions?

## Restrictions

This assignment is about modelling. You are **not required** to implement the complete system in Python.

A very small Python class example is allowed, but it is not the main assessment target.

## Assessment rubric

| Criterion | Weight |
|---|---:|
| Clear requirement | 15% |
| Candidate object identification | 25% |
| Identity/state/behavior reasoning | 30% |
| Relationships | 15% |
| Reflection and justification | 15% |
| **Total** | **100%** |
