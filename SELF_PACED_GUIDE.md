# Self-Paced Learning Guide

There is no fixed schedule for this course.

Progress when you can explain and apply the current module, not merely when you have read it.

## Suggested rhythm per module

```text
1. Read the module README
2. Read the assigned source sections
3. Run the notebook examples
4. Modify the examples
5. Complete selected exercises
6. Attempt the quiz without looking up answers
7. Complete the coding lab / assignment
8. Explain your solution in your own words
9. Move forward when the core ideas are clear
```

## Suggested pace

These are examples, not requirements.

### Intensive

- 2–3 modules per week
- suitable for learners already comfortable with Python

### Standard

- 1 module per week
- gives time for exercises and coding labs

### Deep study

- 1 module every 1–2 weeks
- suitable when combining this course with work or other study

## Checkpoints

### After Module 7

Attempt the Mid-Course Assessment.

### After Module 12

Read the Final Project brief and begin planning.

### After Module 15

Your Final Project should have a working object model, polymorphism, contracts, and tests.

### Module 16

Complete the project, run the tests, and explain the design.

## When to repeat a module

Repeat or review when you cannot yet answer questions such as:

- Which object owns this responsibility?
- Is this relationship is-a or has-a?
- Why does this polymorphic call choose this method?
- What invariant protects this object's state?
- Which test verifies collaboration?

There is no penalty for taking more time.
