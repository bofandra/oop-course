# Module 16 — Final Project Submission Checklist

Use this checklist before submission.

## Analysis & design

- [ ] I rewrote the requirement in my own words.
- [ ] I identified candidate classes myself.
- [ ] Every major class has a clear responsibility.
- [ ] I identified important state and behavior.
- [ ] I documented object relationships.
- [ ] I created a class diagram.
- [ ] My inheritance relationships represent a meaningful is-a relationship.
- [ ] My object-reference relationships are not incorrectly modeled as inheritance.
- [ ] I documented at least one invariant or important contract rule.

## Implementation

- [ ] My program runs without a web framework, database, GUI, or external service.
- [ ] Objects collaborate through references rather than duplicated data where appropriate.
- [ ] Important internal state is encapsulated.
- [ ] I use inheritance where justified.
- [ ] I demonstrate overriding/polymorphism for assignment/scoring variation.
- [ ] I do not use a long type-based branch to simulate polymorphism.
- [ ] Invalid operations raise clear built-in exceptions.
- [ ] Failed operations do not leave objects in invalid states.
- [ ] Source files are organized clearly.

## Testing

- [ ] I test independent class state.
- [ ] I test collaborating objects.
- [ ] I test course capacity.
- [ ] I test enrollment rules.
- [ ] I test at least two scoring/assignment variants.
- [ ] I test submission state changes.
- [ ] I test an invalid operation.
- [ ] I test grading.
- [ ] I have at least one complete end-to-end scenario.
- [ ] All tests execute successfully.

## Documentation

- [ ] README explains the design rather than only how to run the code.
- [ ] Class diagram matches the implementation.
- [ ] Important contracts are documented.
- [ ] I can trace requirements to code and tests.
- [ ] I explain any optional abstraction I added and why it is useful.

## Demo / viva

- [ ] I can explain the complete object flow in 5–7 minutes.
- [ ] I can explain one inheritance decision.
- [ ] I can demonstrate one polymorphic runtime call.
- [ ] I can explain one exception rule.
- [ ] I can run one relevant test.
- [ ] I can modify a small section of my own code if asked.
- [ ] I understand every submitted line well enough to defend it.
